# Schema audit: NAS performance, container security, Jellyfin compatibility

October 2026 · target: Docker on a UGREEN NASync DXP4800+ (8 GB RAM, HDD RAID) next to Jellyfin.

## Summary

Schema was already in good shape before this audit:

* SQLite runs in WAL mode.
* Provider calls go through a cache (SQLite plus an in-memory LRU) with a TTL on each entry, and the provider rate limits are implemented carefully, including AniDB's daily cap and ban latch.
* File operations are atomic, never overwrite, and keep an undo journal.
* Templates run in a sandbox with an allow-list and no `eval`.
* Every path is checked against the allowed roots using `realpath`.
* The container runs as PUID/PGID through gosu.

The problems found were specific, so they were fixed in place. Redis and Celery are **not** needed. Every bottleneck had an in-process fix that suits a single-container SQLite app on a NAS.

Verification:

* Backend: `ruff check .` passes, and `pytest` gives 1282 passed, 24 skipped after the follow-up round (1219 after the first round).
* Frontend: typecheck, lint, 66 tests and `vite build` all pass. The Docker image builds with the new `regex` dependency.
* Container: the image was built and run with the hardened flags. The app process ran as uid 1000 with `CapEff=0` and `NoNewPrivs=1`. The setup code was printed to the log. A WebSocket with a foreign Origin got 403, setup without the code got 403, and `/api/openapi.json` returned 404.

## 1. Refactoring and optimization plan (implemented)

| Change | Where |
|---|---|
| **Missing indexes.** Added indexes on `operations.item_id` (deleting a job's items used to full-scan `operations` once per item while holding the write lock), `job_items.status`, a covering `operations(status, mode, bytes)` for the dashboard totals the UI re-fetches every second, and `events.job_id`. A v2 migration creates them on existing databases. | `models.py`, `db.py` |
| **SQLite settings.** Added `journal_size_limit=64 MiB` so the WAL can't stay as big as the largest match save, and `temp_store=MEMORY`. | `db.py`, `providers/cache.py` |
| **Event loop no longer blocked by render and plan.** Template evaluation for the whole batch runs in a worker thread. Planning runs in **one** thread hop per batch instead of one per item. | `core/pipeline.py` |
| **Sidecar lookup is no longer O(n²).** Each folder's sorted listing is cached, keyed by the folder's mtime (and only once that mtime is 3 s or more old, so coarse SMB timestamps can't hide a new file). Lookup is a binary search on the prefix. Before, a flat 10k-file download folder was rescanned completely three times per video. | `services/fileops.py` |
| **Execute progress is throttled.** The job is re-counted and published at most once a second instead of after every file (O(n²) at 50k files). | `core/pipeline.py` |
| **Media probing runs in parallel.** Up to 3 `mediainfo`/`ffprobe` run at once instead of one at a time. | `core/pipeline.py` |
| **WebSocket bursts no longer leave a stale UI.** Before, a client whose queue overflowed silently lost messages: a 10k-item match lost about 9k `item.updated`. Now the backlog is discarded and one `resync` message is sent, and the SPA refetches what is on screen. | `services/events.py`, `frontend/src/api/wsReducer.ts` |
| **HTTP cache purge.** Expired rows are purged at startup. `purge_expired()` existed but was never called. | `core/matcher.py` |
| **NAS resource limits.** `cpus: 2`, `mem_limit: 1536m` and `pids_limit`, so a large job can't starve Jellyfin transcoding. | `deploy/ugreen/docker-compose.yml` |

### Follow-up round (implemented)

| Change | Where |
|---|---|
| **Paged, slim job items.** `GET /jobs/{id}/items` uses a keyset cursor (`after`), with `status` and `q` filters and per-status counts. The list and WebSocket `item.updated` send a slim item: the selected candidate only, without overview, aliases or genres. `GET /items/{id}` returns the full item, which the inspector loads on open. Bulk actions and execute can target a server-side filter, with a Gmail-style "select all N matching". The workspace loads pages as you scroll inside the existing virtualizer. `GET /jobs/{id}` stays backward compatible but returns at most 1000 items. | `api/jobs.py`, `services/jobs.py`, `api_models.py`, `frontend/src/features/jobs/*`, `api/hooks.ts`, `api/wsReducer.ts` |

### Recommended next (not implemented; larger changes)

1. **Store fewer candidates.** Items still store up to 10 full candidates in the database (only the API payloads are slim now). Keeping the top 3 would shrink `job_items`.
2. **Coalesce bulk publishes.** Send one `job.items_changed` per match save, bulk action or rematch instead of one message per item. With `resync` in place this is now an optimization, not a correctness issue.
3. **Save match results per chunk.**
   - Today nothing is saved until the end, so a crash at 90% loses all matching.
   - Also bulk-load items in `_save_works`, which currently does one `session.get` per item.
   - And build `_item_context` from a narrow column query.
4. **Watch folders.**
   - In copy or link mode, every file is offered again after a restart. Skip paths that already have a done operation with the same size and mtime.
   - Rescan every 15–30 min, not every 60 s, when inotify is working.
5. **Byte-compare only once.** `_identical` can read source and destination fully up to three times per item. Do the full compare only in `_Execution.run`.
6. **Copy path.**
   - Call `posix_fadvise(DONTNEED)` while copying large files, so they don't evict SQLite pages from the page cache.
   - Use `os.copy_file_range` for COPY mode on the same device (a reflink on Btrfs).
7. **AniDB.** Build the title index and run `process.extract` in a worker thread, and parse JSON once in `providers/http.py`.

## 2. Security hardening checklist

### Implemented

- [x] **First-run takeover closed.**
  - Creating the first admin needs a one-time setup code. It is generated and printed to `docker logs`, or set with `SCHEMA_SETUP_TOKEN`.
  - The count-then-insert is now atomic.
  - The setup page asks for the code.
  - Before this, anyone on the LAN (or a DNS-rebinding page) could claim a fresh instance.
- [x] **Login throttling.**
  - Up to 10 failures per IP and 30 per username in 15 minutes, then 429 with `Retry-After`.
  - The check runs **before** scrypt, so guessing can't load the NAS CPU.
  - Behind a reverse proxy, set `FORWARDED_ALLOW_IPS`.
- [x] **WebSocket Origin check.**
  - `Origin` must match `Host` (or be listed in `SCHEMA_ALLOWED_ORIGINS`).
  - SameSite=Lax ignores ports, so another web UI on the NAS could otherwise read the event stream with the user's cookie.
  - The Vite dev proxy no longer rewrites `Host`.
- [x] **DNS rebinding.** Optional `SCHEMA_ALLOWED_HOSTS` turns on Starlette's `TrustedHostMiddleware`; loopback is always allowed for the healthcheck.
- [x] **Undo can't be abused through a tampered trash manifest.**
  - Restores only accept plain files directly inside the trash slot.
  - The manifest sits on the user-writable share. An edited one could make undo copy `/config/schema.db` or `secret.key` into the library and delete the original.
- [x] **Template engine can't exhaust memory.**
  - Pad widths are capped at 255, method text arguments at 1024 characters, and every intermediate string at 64 KiB.
  - String repetition is checked *before* the string is built.
  - Before this, `{('x'*1000)*1000*1000}` built 1 GB.
- [x] **Media-server token exfiltration closed.**
  - A masked token can't be reused after the server URL changes, in either save or test.
  - Redirects are no longer followed, so a custom `X-*-Token` header doesn't follow a cross-origin redirect.
- [x] **Secrets at rest.**
  - `schema.db*` and `cache.sqlite3*` (password hashes, provider keys, media-server tokens, the TVDB bearer token) are set to `0600` whatever `UMASK` is. Unraid's default is `000`.
- [x] **API key in logs.** `?apikey=` is redacted in the uvicorn access log.
- [x] **OpenAPI docs** are off unless `SCHEMA_API_DOCS=1`.
- [x] **Container settings.** `no-new-privileges`, `cap_drop: ALL` and `cap_add` for only `CHOWN, DAC_OVERRIDE, FOWNER, SETGID, SETUID`, which the entrypoint needs. The app itself runs with no capabilities. `pids_limit` is set, and the compose file notes how to bind one LAN address and mount only the folders Schema needs.

- [x] **ReDoS (follow-up round).**
  - User template regexes now run through the `regex` package (V0, re-compatible) behind a `GuardedPattern` wrapper. Each call has a total budget of 0.25 s and raises a clear format error on timeout.
  - Fixed internal patterns stay on `re`.
  - The two audit bypasses now finish in about 0 ms. Variants that still backtrack are stopped at 0.25 s.
  - Remaining gap: the budget is per call, so a template chaining many slow calls can still add up across `validate()` samples.
- [x] **Session revocation (follow-up round).**
  - `users.session_epoch` was added with a v3 migration. Cookies carry the epoch; older cookies count as epoch 0 and keep working.
  - `POST /api/auth/logout-all` revokes every session.
  - `POST /api/auth/password` rehashes, revokes other sessions and keeps this browser signed in. It is throttled.
  - Open WebSockets re-check their session every 60 s, and immediately on revoke.
  - Settings has a new **Account** tab.
  - Plain logout still signs out only this browser.

### Recommended next

- [ ] **Symlinks.** Check symlinked source files against the allowed roots *before* probing or hashing them.
- [ ] **scrypt cost.** Raise N to 2^17 and rehash on the next login; this is backward compatible.
- [ ] **Base images.** Pin them by digest and install from a hashed lockfile.
- [ ] **Read-only root filesystem.** Possible with `user: "PUID:PGID"`, `read_only: true` and a tmpfs `/tmp`. The entrypoint already skips `useradd` when it isn't root.

## 3. Jellyfin compatibility and dry-run safety

**Already correct:**

* The `jellyfin-*` presets give `Title (Year) [tmdbid-…]/Title (Year).ext` and `Show (Year) [tvdbid-…]/Season 01/Show (Year) - S01E01 - Title.ext`.
* Specials go to `Season 00` as `S00Exx`, multi-episode files are named `S01E01-E02`, and multi-part files `- ptN`.
* Names are sanitized for SMB:
  * `<>:"/\|?*` are handled, with `:` turned into ` - `.
  * Trailing dots and spaces are removed.
  * Reserved names (`CON`, `NUL`) are fixed.
  * The 255 limit is counted in **UTF-8 bytes**.
* `..` and absolute paths are rejected.
* Collisions within a batch are detected case-insensitively, with ` - 1080p` version suffixes added.
* Conflicts are checked again at execution time, and renames never overwrite.

**Fixed:**

* **`upgrade` could downgrade.** Files Schema named have no quality tags, so they ranked 0 and any incoming 720p "upgraded" an existing 2160p. Now the existing file is probed for its resolution, and if that's impossible the item is skipped instead of guessing.
* **Hidden replacements.** Under `overwrite`, `upgrade` and `index`, an existing destination file now shows a warning in the preview (`replaces_existing`, `upgrade_existing` or `indexed_existing`). It used to look like a plain "matched".
* **Editions dropped.** Jellyfin, Emby and Kodi movie presets now keep the edition, for example `Blade Runner (1982) - Final Cut.mkv`. That is Jellyfin's multi-version label. Before, two cuts rendered to the same name and one replaced the other.

**Fixed in the follow-up round:**

* **Dry runs no longer use up the job.**
  * After a "test" run, items return to matched/approved, and the job settles to ready or review.
  * The would-be destination shows as `dry_run_ok: <path>`. Problems a real run would hit show as `dry_run_failed` with the reason, and the item stays runnable.
  * A real run of the same job works straight away, and undoing a test operation never touches the item.
* **Anime sequels in one series folder.**
  * When Anime-Lists maps an AniDB entry onto a TVDB or TMDB series, the series name and year come from that mapped series. The lookup is cached and made once per batch.
  * The ID tag follows the numbering target (`[tmdbid-…]` for TMDB, `[tvdbid-…]` for TVDB), via a new `{db}` binding.
  * Caveat: without a TVDB/TMDB key the AniDB name is kept, so seasons still split. The ID tag is still correct.
* **Capitalisation and Unicode duplicates.**
  * Missing destination folders reuse an existing folder whose name differs only in case or NFC/NFD form, so `Doctor who` goes into the existing `Doctor Who`. The preview shows the reused name.
  * A file name that differs only that way counts as a conflict and follows the normal policy (trash, index, skip).
  * Rendered names are now NFC.
  * Caveat: when a run creates many new folders in one large flat folder, that parent folder is re-listed once per new folder.

**Recommended next:**

1. **Same stem, different extension.** A video with the same name but a different extension (an existing `.avi` vs an incoming `.mkv`) is still not treated as a conflict, so `upgrade` never triggers for it.
2. **Long titles.**
   - Hold back about 32 bytes for sidecar suffixes when trimming long names. Otherwise a `.en.forced.srt` stem gets cut shorter than the video's stem, and Jellyfin no longer links the subtitle.
   - Trim the title part before the `(Year) [id]` tail, not the end of the string.
3. **Same-batch checks.**
   - After a manual edit, re-check collisions for every item in the job, not just the edited one.
   - Refuse bulk approval of `duplicate_in_batch` items.
   - Check across all queued jobs at enqueue time.
4. **Presets.**
   - Fall back to `{airdate}` for daily shows.
   - Send episodic items with no `SxxExx` and no air date to review.
   - Use ` - 2` instead of ` (1)` for `index` names; Jellyfin only recognizes ` - label`.
   - Route extras into `extras/` and `trailers/`.
   - Pick up `Subs/` folders and `-poster`/`-fanart` images.
5. **Music isn't supported**, so there are no `Disc 1`/`CD1` layouts. That is a feature gap rather than a bug.
